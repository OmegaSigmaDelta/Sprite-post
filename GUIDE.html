Как запустить сайт

Сайт состоит из набора файлов без сборки. Данные (чат, файлы, участники) хранятся в бесплатном Supabase, сами файлы сайта лежат на любом статическом хостинге. На всё уйдёт около получаса. Платить не нужно.

1Что понадобится

  • Бесплатный аккаунт на supabase.com.
  • Место, где будет жить сайт: Netlify, GitHub Pages или Cloudflare Pages (шаг 7). Подойдёт любой, главное чтобы был HTTPS.
  • Папка с файлами сайта в таком виде:
sprite-post/
├── index.html
├── app.js
├── config.js          <- сюда впишете адрес и ключ (шаг 4)
├── styles.css
├── sw.js
├── manifest.webmanifest
├── GUIDE.html         <- это руководство
├── icons/
│   ├── icon.svg
│   ├── icon-192.png
│   ├── icon-512.png
│   ├── icon-maskable-512.png
│   └── apple-touch-icon.png
├── vendor/
│   └── supabase.js    <- по желанию (шаг 5)
└── supabase/
    ├── schema.sql          <- нужен на шаге 3
    └── releases-cron.sql   <- нужен на шаге 9, если захотите

Репозиторий игры на GitHub нужен только для вкладки «Релизы». Для остального он не требуется.

2Проект в Supabase

  1. Войдите в Supabase и нажмите New project.
  2. Название любое, например sprite-post. Регион выберите ближайший к вам (для Европы подойдёт Frankfurt).
  3. Придумайте пароль базы данных и сохраните его. Сайту он не нужен, но восстановить его сложно.
  4. Нажмите Create new project и подождите пару минут, пока проект подготовится.

3База данных и вход

3а. Таблицы и права

  1. В левом меню Supabase откройте SQL Editor, затем New query.
  2. Откройте файл supabase/schema.sql (или раскройте текст ниже), скопируйте всё содержимое и вставьте в редактор.
  3. Нажмите Run. Должно появиться сообщение «Success. No rows returned». Если вылезла ошибка, пришлите её текст, а не запускайте скрипт по частям.

Скрипт создаёт таблицы, правила доступа, хранилище файлов sprites и включает живые обновления. Его можно запускать повторно.

-- Sprite Post: база данных. Выполняется один раз в Supabase: SQL Editor -> New query -> Run.
-- Скрипт можно запускать повторно, ничего не сломается.

-- ============ 1. Таблицы ============

create table if not exists public.profiles (
  id             uuid primary key references auth.users(id) on delete cascade,
  name           text not null check (char_length(name) between 1 and 40),
  role           text check (role in ('developer', 'artist')),
  requested_role text not null default 'artist' check (requested_role in ('developer', 'artist')),
  approved       boolean not null default false,
  created_at     timestamptz not null default now()
);

create table if not exists public.files (
  id          uuid primary key default gen_random_uuid(),
  uploader    uuid default auth.uid() references public.profiles(id) on delete set null,
  name        text not null check (char_length(name) between 1 and 120),
  mime        text,
  size        bigint not null check (size > 0),
  path        text not null unique,
  note        text check (note is null or char_length(note) <= 140),
  via_message boolean not null default false,
  created_at  timestamptz not null default now()
);

create table if not exists public.messages (
  id         uuid primary key default gen_random_uuid(),
  author     uuid default auth.uid() references public.profiles(id) on delete set null,
  body       text check (body is null or char_length(body) <= 2000),
  file_ids   uuid[],
  reply_to   uuid,   -- без внешнего ключа: после удаления оригинала в чате видно «сообщение удалено»
  reply_file uuid,
  created_at timestamptz not null default now(),
  check (body is not null or coalesce(array_length(file_ids, 1), 0) > 0),
  check (coalesce(array_length(file_ids, 1), 0) <= 20)
);
create index if not exists messages_created_idx on public.messages (created_at desc);
create index if not exists files_created_idx on public.files (created_at desc);

create table if not exists public.releases (
  gh_id        bigint primary key,
  tag          text not null default '',
  name         text not null default '',
  body         text not null default '',
  prerelease   boolean not null default false,
  html_url     text not null default '',
  published_at timestamptz,
  assets       jsonb not null default '[]'::jsonb,
  shared       boolean not null default false,
  synced_at    timestamptz
);

create table if not exists public.settings (
  key   text primary key,
  value text
);

-- ============ 2. Помощники для проверки прав ============

create or replace function public.sp_is_approved() returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from public.profiles where id = auth.uid() and approved);
$$;

create or replace function public.sp_is_dev() returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from public.profiles where id = auth.uid() and approved and role = 'developer');
$$;

-- ============ 3. Регистрация: кодовое слово и первый разработчик ============

create or replace function public.sp_handle_new_user() returns trigger
language plpgsql security definer set search_path = public as $$
declare
  meta  jsonb := coalesce(new.raw_user_meta_data, '{}'::jsonb);
  inv   text;
  given text;
  want  text;
  nm    text;
begin
  select value into inv from public.settings where key = 'invite';
  given := lower(trim(coalesce(meta->>'invite', '')));
  if inv is null or given = '' or given <> lower(trim(inv)) then
    raise exception 'invalid_invite';
  end if;

  want := case when meta->>'role' = 'developer' then 'developer' else 'artist' end;
  nm := left(coalesce(nullif(trim(meta->>'name'), ''), 'Участник'), 40);

  if not exists (select 1 from public.profiles where role = 'developer' and approved) then
    -- Первый зарегистрированный становится разработчиком сразу.
    insert into public.profiles (id, name, role, requested_role, approved)
    values (new.id, nm, 'developer', 'developer', true);
  else
    insert into public.profiles (id, name, role, requested_role, approved)
    values (new.id, nm, null, want, false);
  end if;
  return new;
end;
$$;

drop trigger if exists sp_on_auth_user_created on auth.users;
create trigger sp_on_auth_user_created
  after insert on auth.users
  for each row execute function public.sp_handle_new_user();

-- ============ 4. Управление участниками (вызывается из приложения) ============

create or replace function public.set_member(target uuid, do_approve boolean, new_role text default null)
returns void language plpgsql security definer set search_path = public as $$
begin
  if not public.sp_is_dev() then raise exception 'forbidden'; end if;
  if target = auth.uid() then raise exception 'Нельзя менять собственную роль и доступ'; end if;
  if do_approve then
    update public.profiles set approved = true, role = coalesce(new_role, requested_role) where id = target;
  else
    update public.profiles set approved = false, requested_role = coalesce(role, requested_role), role = null where id = target;
  end if;
end;
$$;

create or replace function public.remove_member(target uuid)
returns void language plpgsql security definer set search_path = public as $$
begin
  if not public.sp_is_dev() then raise exception 'forbidden'; end if;
  if target = auth.uid() then raise exception 'Нельзя удалить самого себя'; end if;
  delete from auth.users where id = target;
end;
$$;

revoke all on function public.set_member(uuid, boolean, text) from public, anon;
revoke all on function public.remove_member(uuid) from public, anon;
grant execute on function public.set_member(uuid, boolean, text) to authenticated;
grant execute on function public.remove_member(uuid) to authenticated;
grant execute on function public.sp_is_approved() to authenticated;
grant execute on function public.sp_is_dev() to authenticated;

-- ============ 5. Правила для файлов: размер и общий лимит ============
-- Если меняете лимиты, меняйте и в config.js (STORAGE_LIMIT_MB, MAX_FILE_MB).

create or replace function public.sp_check_file() returns trigger
language plpgsql security definer set search_path = public as $$
begin
  if new.size > 30 * 1048576 then
    raise exception 'Файл больше 30 МБ';
  end if;
  if split_part(new.path, '/', 1) <> new.uploader::text then
    raise exception 'Неверный путь файла';
  end if;
  if (select coalesce(sum(size), 0) from public.files) + new.size > 900::bigint * 1048576 then
    raise exception 'storage_quota';
  end if;
  return new;
end;
$$;

drop trigger if exists sp_files_check on public.files;
create trigger sp_files_check before insert on public.files
  for each row execute function public.sp_check_file();

alter table public.profiles enable row level security;
alter table public.files    enable row level security;
alter table public.messages enable row level security;
alter table public.releases enable row level security;
alter table public.settings enable row level security;

revoke all on public.profiles, public.files, public.messages, public.releases, public.settings from anon;
grant usage on schema public to authenticated;
grant select on public.profiles to authenticated;
grant select, insert, delete on public.files, public.messages to authenticated;
grant select, insert, update, delete on public.releases, public.settings to authenticated;

-- profiles: свою строку видит каждый, остальных видят подтверждённые (неподтверждённых только разработчик)
drop policy if exists sp_profiles_select on public.profiles;
create policy sp_profiles_select on public.profiles for select to authenticated
  using (id = auth.uid() or (public.sp_is_approved() and (approved or public.sp_is_dev())));

-- messages
drop policy if exists sp_messages_select on public.messages;
create policy sp_messages_select on public.messages for select to authenticated
  using (public.sp_is_approved());
drop policy if exists sp_messages_insert on public.messages;
create policy sp_messages_insert on public.messages for insert to authenticated
  with check (public.sp_is_approved() and author = auth.uid());
drop policy if exists sp_messages_delete on public.messages;
create policy sp_messages_delete on public.messages for delete to authenticated
  using (public.sp_is_approved() and (author = auth.uid() or public.sp_is_dev()));

-- files
drop policy if exists sp_files_select on public.files;
create policy sp_files_select on public.files for select to authenticated
  using (public.sp_is_approved());
drop policy if exists sp_files_insert on public.files;
create policy sp_files_insert on public.files for insert to authenticated
  with check (public.sp_is_approved() and uploader = auth.uid());
drop policy if exists sp_files_delete on public.files;
create policy sp_files_delete on public.files for delete to authenticated
  using (public.sp_is_approved() and (uploader = auth.uid() or public.sp_is_dev()));

-- releases: разработчик видит всё, художник только открытые
drop policy if exists sp_releases_select on public.releases;
create policy sp_releases_select on public.releases for select to authenticated
  using (public.sp_is_dev() or (public.sp_is_approved() and shared));
drop policy if exists sp_releases_insert on public.releases;
create policy sp_releases_insert on public.releases for insert to authenticated
  with check (public.sp_is_dev());
drop policy if exists sp_releases_update on public.releases;
create policy sp_releases_update on public.releases for update to authenticated
  using (public.sp_is_dev()) with check (public.sp_is_dev());
drop policy if exists sp_releases_delete on public.releases;
create policy sp_releases_delete on public.releases for delete to authenticated
  using (public.sp_is_dev());

-- settings: кодовое слово видит только разработчик
drop policy if exists sp_settings_select on public.settings;
create policy sp_settings_select on public.settings for select to authenticated
  using (public.sp_is_approved() and (key <> 'invite' or public.sp_is_dev()));
drop policy if exists sp_settings_insert on public.settings;
create policy sp_settings_insert on public.settings for insert to authenticated
  with check (public.sp_is_dev());
drop policy if exists sp_settings_update on public.settings;
create policy sp_settings_update on public.settings for update to authenticated
  using (public.sp_is_dev()) with check (public.sp_is_dev());
drop policy if exists sp_settings_delete on public.settings;
create policy sp_settings_delete on public.settings for delete to authenticated
  using (public.sp_is_dev());

values ('sprites', 'sprites', false, 31457280)
on conflict (id) do update set public = false, file_size_limit = excluded.file_size_limit;

create policy sp_storage_select on storage.objects for select to authenticated
  using (bucket_id = 'sprites' and public.sp_is_approved());

drop policy if exists sp_storage_insert on storage.objects;
create policy sp_storage_insert on storage.objects for insert to authenticated
  with check (bucket_id = 'sprites' and public.sp_is_approved()
              and (storage.foldername(name))[1] = auth.uid()::text);

drop policy if exists sp_storage_delete on storage.objects;
create policy sp_storage_delete on storage.objects for delete to authenticated
  using (bucket_id = 'sprites' and public.sp_is_approved()
         and ((storage.foldername(name))[1] = auth.uid()::text or public.sp_is_dev()));

-- ============ 8. Живые обновления (Realtime) ============

do $$
declare t text;
begin
  foreach t in array array['messages', 'files', 'releases', 'profiles', 'settings'] loop
    if not exists (select 1 from pg_publication_tables
                   where pubname = 'supabase_realtime' and schemaname = 'public' and tablename = t) then
      execute format('alter publication supabase_realtime add table public.%I', t);
    end if;
  end loop;
end;
$$;

3б. Кодовое слово для регистрации

Без кодового слова никто не сможет создать аккаунт. Выполните ещё один запрос, заменив слово на своё (в SQL Editor снова New query):

insert into public.settings (key, value)
values ('invite', 'моё-кодовое-слово')
on conflict (key) do update set value = excluded.value;

Позже слово можно менять прямо в приложении: вкладка «Ещё», раздел «Кодовое слово для регистрации».

3в. Отключите подтверждение почты

Сайт не отправляет писем, поэтому подтверждение почты нужно выключить, иначе вход не заработает.

  1. В Supabase откройте Authentication, затем Sign In / Providers и выберите Email.
  2. Выключите переключатель Confirm email.
  3. Там же поставьте минимальную длину пароля 8 (необязательно, сайт и так требует 8).
  4. Нажмите Save.
Названия пунктов в Supabase иногда меняются. Если не нашли, ищите в разделе Authentication настройки провайдера Email и пункт про подтверждение почты.

4Адрес и ключ в config.js

  1. В Supabase откройте Project Settings, затем API Keys (адрес проекта показан там же или в разделе Data API).
  2. Скопируйте Project URL. Он выглядит как https://abcdefghij.supabase.co.
  3. Скопируйте Publishable key (начинается с sb_publishable_) либо ключ anon public, если у проекта старый формат.
  4. Откройте config.js в любом текстовом редакторе и замените только текст в кавычках:
config.js
SUPABASE_URL: "https://abcdefghij.supabase.co",
SUPABASE_KEY: "sb_publishable_xxxxxxxxxxxxxxxx",
Ключи secret и service_role вставлять нельзя: они открывают базу целиком. Публичный ключ в этом файле безопасен, потому что доступ защищён правилами из шага 3.

Здесь же можно поменять репозиторий игры (DEFAULT_REPO) и лимиты. Если меняете лимит хранилища или размер файла, поменяйте и в schema.sql (числа 900 и 30 в разделе 5), иначе сервер будет строже сайта.

5Библиотека Supabaseпо желанию

Сайт сначала ищет файл vendor/supabase.js, а если его нет, берёт библиотеку с сервера jsDelivr. Обычно этого достаточно. Свой файл нужен, если jsDelivr у вас или у художника не открывается.

  1. Откройте в браузере эту ссылку.
  2. Сохраните страницу как файл (Ctrl+S) под именем supabase.js в папку vendor.

6Проверка на своём компьютере

Двойной щелчок по index.html не сработает: браузер блокирует модули при открытии файла напрямую. Нужен маленький локальный сервер. Если на компьютере есть Python, откройте терминал в папке сайта и выполните:

python3 -m http.server 8080

Затем откройте http://localhost:8080. Если вместо формы входа вы видите «Сайт ещё не настроен», проверьте шаг 4. Эту проверку можно пропустить и сразу перейти к шагу 7.

7Выложить в интернет

Выберите один способ. Все три бесплатные и дают HTTPS, который нужен для установки на телефон и уведомлений.

Вариант А: Netlify Drop (проще всего)

  1. Откройте app.netlify.com/drop и войдите.
  2. Перетащите всю папку сайта в окно. Через несколько секунд получите адрес вида https://что-то.netlify.app.
  3. Чтобы обновить сайт, перетащите папку заново в раздел Deploys.

Вариант Б: GitHub Pages

  1. Создайте на GitHub новый репозиторий (публичный) и загрузите в него все файлы сайта: Add file → Upload files.
  2. Откройте Settings → Pages, в Source выберите Deploy from a branch, ветку main и папку / (root), нажмите Save.
  3. Через минуту-две сайт появится по адресу https://ваше-имя.github.io/название-репозитория/.

Вариант В: Cloudflare Pages

В Cloudflare откройте Workers & Pages → Create → Pages → Upload assets, перетащите папку сайта и нажмите Deploy.

Все пути на сайте относительные, поэтому он работает и в подпапке (как на GitHub Pages).

8Первый вход и приглашение художника

  1. Откройте адрес сайта, перейдите на вкладку Регистрация.
  2. Заполните имя, почту, пароль и кодовое слово из шага 3б. Первым должны зарегистрироваться вы: первый человек автоматически становится разработчиком и сразу получает доступ.
  3. Отправьте художнику адрес сайта и кодовое слово. Лучше передать их разными каналами.
  4. Художник регистрируется сам. Пока вы его не подтвердили, он видит экран «Ждём подтверждения».
  5. У вас появится уведомление «Новая заявка». Откройте Ещё → Участники и нажмите «Принять». Роль можно выбрать любую, независимо от того, что человек запросил.

Установка на телефон

  • Android (Chrome): меню ⋮ → «Установить приложение» или «Добавить на главный экран».
  • iPhone (Safari): кнопка «Поделиться» → «На экран Домой». Уведомления на iPhone работают только из установленной иконки.

9Сверка релизов в фонепо желанию

Без этого шага релизы подтягиваются, когда разработчик открывает сайт, затем раз в 15 минут, пока страница открыта, и по кнопке «Проверить сейчас». Этого достаточно, если вы часто заходите. Чтобы база сама проверяла GitHub круглые сутки:

  1. В Supabase откройте Database → Extensions и убедитесь, что pg_net и pg_cron включены (скрипт попробует включить их сам).
  2. В SQL Editor выполните содержимое supabase/releases-cron.sql (или текст ниже).
  3. В приложении на вкладке «Релизы» укажите репозиторий и нажмите «Сохранить».
Показать releases-cron.sql
-- Sprite Post: автосверка релизов с GitHub прямо в базе (необязательно, шаг 9 руководства).
-- Каждые 15 минут база сама спрашивает GitHub и обновляет список релизов,
-- даже если ни одна страница не открыта. Репозиторий должен быть публичным.

create extension if not exists pg_net with schema extensions;
create extension if not exists pg_cron;

-- Шаг 1: отправить запрос к GitHub.
create or replace function public.sp_request_releases() returns void
language plpgsql security definer set search_path = public, extensions as $$
declare
  repo text;
  rid  bigint;
begin
  select coalesce((select value from public.settings where key = 'repo'),
                  'OmegaSigmaDelta/Sierra-Tango-Kasper-Echo') into repo;
  if repo !~ '^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$' then return; end if;

  select net.http_get(
    url := 'https://api.github.com/repos/' || repo || '/releases?per_page=30',
    headers := jsonb_build_object('Accept', 'application/vnd.github+json', 'User-Agent', 'sprite-post')
  ) into rid;

  insert into public.settings (key, value) values ('gh_request', rid::text)
  on conflict (key) do update set value = excluded.value;
end;
$$;

-- Шаг 2: через пару минут забрать ответ и записать релизы.
create or replace function public.sp_apply_releases() returns void
language plpgsql security definer set search_path = public as $$
declare
  rid  bigint;
  resp record;
  j    jsonb;
  r    jsonb;
  ids  bigint[] := '{}';
  pre  boolean;
  ast  jsonb;
begin
  select value::bigint into rid from public.settings where key = 'gh_request';
  if rid is null then return; end if;

  select status_code, content into resp from net._http_response where id = rid;
  if not found or resp.status_code is distinct from 200 then return; end if;

  j := resp.content::jsonb;
  if jsonb_typeof(j) <> 'array' then return; end if;

  for r in select * from jsonb_array_elements(j) loop
    if coalesce((r->>'draft')::boolean, false) then continue; end if;
    pre := coalesce((r->>'prerelease')::boolean, false);
    select coalesce(jsonb_agg(jsonb_build_object(
             'name', a->>'name', 'size', (a->>'size')::bigint, 'url', a->>'browser_download_url')), '[]'::jsonb)
      into ast
      from jsonb_array_elements(coalesce(r->'assets', '[]'::jsonb)) a;

    insert into public.releases (gh_id, tag, name, body, prerelease, html_url, published_at, assets, shared, synced_at)
    values ((r->>'id')::bigint, coalesce(r->>'tag_name', ''), coalesce(r->>'name', ''), coalesce(r->>'body', ''),
            pre, coalesce(r->>'html_url', ''), coalesce(r->>'published_at', r->>'created_at')::timestamptz,
            ast, not pre, now())
    on conflict (gh_id) do update set
      tag = excluded.tag, name = excluded.name, body = excluded.body, prerelease = excluded.prerelease,
      html_url = excluded.html_url, published_at = excluded.published_at, assets = excluded.assets,
      synced_at = excluded.synced_at;   -- поле shared не трогаем: выбор разработчика сохраняется
    ids := ids || (r->>'id')::bigint;
  end loop;

  if coalesce(array_length(ids, 1), 0) < 30 then
    delete from public.releases where not (gh_id = any (ids));
  end if;

  insert into public.settings (key, value) values ('releases_synced_at', to_char(now() at time zone 'utc', 'YYYY-MM-DD"T"HH24:MI:SS"Z"'))
  on conflict (key) do update set value = excluded.value;
  delete from public.settings where key = 'gh_request';
end;
$$;

revoke all on function public.sp_request_releases() from public, anon, authenticated;
revoke all on function public.sp_apply_releases() from public, anon, authenticated;

-- Расписание: запрос в 0, 15, 30, 45 минут, обработка ответа на 2-й минуте после каждого запроса.
select cron.schedule('sp-releases-request', '*/15 * * * *', 'select public.sp_request_releases()');
select cron.schedule('sp-releases-apply', '2-59/15 * * * *', 'select public.sp_apply_releases()');

Репозиторий должен быть публичным. GitHub ограничивает анонимные запросы (60 в час с одного адреса, а у серверов Supabase адрес общий), поэтому иногда сверка может не пройти. В следующий раз она повторится сама, а кнопка в приложении работает независимо.

11Хорошо знать

  • Бесплатный Supabase засыпает. Проект без активности около недели ставится на паузу. Зайдите в панель Supabase и нажмите Restore, данные сохранятся. Если вы с художником пользуетесь сайтом хотя бы раз в неделю, этого не случится.
  • Места 1 ГБ. Сайт блокирует загрузки на 900 МБ, чтобы не выйти за лимит. Занято ли место, видно на вкладке «Файлы».
  • Забытый пароль. Восстановления нет. Выход: в Supabase откройте Authentication → Users, удалите аккаунт, и человек зарегистрируется заново (его старые сообщения останутся подписанными как «Удалённый участник»).
  • Уведомления приходят, пока сайт открыт во вкладке или в установленном приложении. Фоновых push-уведомлений при закрытом сайте здесь нет.
  • Обновление сайта. Замените изменённые файлы на хостинге. Если у телефона остался старый вид, обновите страницу дважды.
  • Резервная копия. Раз в какое-то время скачивайте важные спрайты из приложения. Бесплатный тариф Supabase не включает резервных копий.
